# Проверка отчётов и оценки (guap-teacher MCP)

Навык закрывает полный цикл: снять ожидающие проверки отчёты по дисциплине,
скачать PDF, провести ревью, согласовать балл с преподавателем и выставить
оценку. Все шаги последовательные, без параллельных запросов к порталу.
Блок оформления (раздел 4) — требования к **лабораторным** работам; для
курсовых работ и их пояснительных записок — навык **guap-kurs-review**
(`skill://guap-kurs-review`).

## 0. Главное правило: оценка — только с согласия преподавателя

> **Оценка ставится ТОЛЬКО с явного согласия преподавателя.** Без
> подтверждённого «ставь»/«соглас»/«подтверждаю» на конкретный балл по
> конкретному отчёту — ничего не отправляем. Молчание, «наверное» и
> «наверное, можно» согласием не считаются.

`grade_report` — единственный write-инструмент, который использует этот
навык (POST `/inside/professor/reports/{id}` с `_method=PATCH`; на сервере
есть ещё edit_task и create_material — к проверке отчётов отношения не
имеют). Порядок всегда такой: ревью с предложенными баллами → явное добро
преподавателя → отправка → сверка ответа. «Молча» оценки не ставим.

## 1. Предусловие: живая сессия

1. `check_auth_status` → `"authenticated": true`? Если нет — `authenticate`
   и повторить проверку.

## 2. Найти дисциплину и отчёты

- `list_reports(subject=<id>, per_page=100)` — только ожидающие проверки
  идут с `status: "ожидает проверки"`; фильтр статуса: `1`=ожидает,
  `2`=принят, `3`=не принят.
- **Нюанс:** нужная дисциплина может не показываться в `list_subjects`
  (бывает, например, с «Основы разработки на Dart (4613МК)»). Тогда берём
  `subject_id` из карточки любого задания этой дисциплины: `get_task`
  → ссылка `/inside/subjects/{id}` в ответе.
- Максимум баллов задания — поле «Макс. баллы за задание» в `get_task`.

## 3. Скачать и открыть отчёты

1. `download_report(report_id, save_dir=<workspace>/.guap_mcp_tmp/<Дисциплина>)`
   — сразу в рабочую папку проекта (`.guap_mcp_tmp` — дефолтный каталог
   скачивания сервера, из ~/Downloads ничего не приходит): PDF-панель ZCode
   открывает только пути внутри workspace. После ревью папку удалить.
2. Открыть `open_document` + `read_document`; длинные PDF — с `cursor`
   (постранично).

## 4. Ревью отчёта (чек-лист)

- **Полнота:** все задания варианта выполнены, у каждого листинг и скриншот.
- **Компилируемость листингов:** типичные артефакты переноса из Word —
  «умные» кавычки `‘…’`, смена регистра переменных (`I` vs `i`). Такой
  листинг в отчёте — замечание, даже если скриншот запуска есть.
- **Соответствие данным варианта:** сравнить литералы в коде с условием
  (частая потеря — минусы у отрицательных чисел, замена символов).
- **Математика:** проверить формулы вручную (дискриминанты, суммы рядов).
- **Формулы-картинки** в условиях (текстовый слой PDF пуст) сверить нельзя —
  пометить «не проверено по тексту», НЕ считать ошибкой студента.
- **Вывод** соответствует сделанному (не упоминает несуществующее).

### Оформление лабораторных работ (правила ГУАП)

Только для отчётов о лабораторных работах. Источник правил —
«Правила оформления учебных работ»: <https://guap.ru/regdocs/docs/uch>;
бланк титульного листа: <https://fs.guap.ru/regdocs/2026/uch/lab.docx>
(бланки института 8 не используем — не наши).

- **Титульный лист по бланку:** шапка (министерство, полное название
  ГУАП, «КАФЕДРА № …»); блок «ОТЧЕТ ЗАЩИЩЕН С ОЦЕНКОЙ» /
  «ПРЕПОДАВАТЕЛЬ» (должность, уч. степень, звание; подпись, дата;
  инициалы, фамилия); «ОТЧЕТ О ЛАБОРАТОРНОЙ РАБОТЕ», «по дисциплине: …»;
  блок «РАБОТУ ВЫПОЛНИЛ» / «СТУДЕНТ гр. № …»; внизу «Санкт-Петербург 20__».
- **Текст:** Times New Roman не менее 12 пт (допустимо 14), выравнивание
  по ширине, абзацный отступ 1,25 см, полуторный интервал; полужирный —
  только заголовки.
- **Структурные элементы** (СОДЕРЖАНИЕ, ВВЕДЕНИЕ, ЗАКЛЮЧЕНИЕ, СПИСОК
  ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ, ПРИЛОЖЕНИЕ): по центру, ПРОПИСНЫМИ, без точки
  в конце и без подчёркивания. Введение и заключение не нумеруются; каждый
  структурный элемент и раздел основной части — с новой страницы.
- **Заголовки разделов/подразделов:** с абзацного отступа, с прописной
  буквы, полужирные, без точки в конце, без переносов слов; нумерация
  арабскими цифрами («1», «1.1») — без точки после номера.
- **Страницы:** номер внизу по центру, без точки; титульный лист входит в
  нумерацию, но номер на нём не ставится.
- **Рисунки:** подпись под рисунком — «Рисунок N — Название»; в тексте
  обязательна ссылка («…в соответствии с рисунком 1»).
- **Таблицы:** название над таблицей слева — «Таблица N — Название»;
  ссылка в тексте обязательна; при переносе таблицы — «Продолжение
  таблицы N» и повтор номера граф.
- **Приложения:** после списка использованных источников, каждое с новой
  страницы; буквы кириллицы, кроме Ё, З, Й, О, Ч, Ъ, Ы, Ь.
- **Список использованных источников:** в порядке появления ссылок в
  тексте; описание каждого источника — по ГОСТ Р 7.0.100-2018.
- Поля (левое 30 мм, правое 15 мм, верх/низ 20 мм) и точный кегль по PDF
  проверяются лишь приблизительно: отмечать грубые отклонения, к
  миллиметрам не придираться.

Недочёты оформления — категория «мелкие замечания» шкалы (M−1). Отсутствие
титульного листа или бланк не по форме — понижение согласовать с
преподавателем, автоматически не штрафуем.

## 5. Протокол проверки (журнал дисциплины и вопросы на понимание)

Большинство работ готовится в ИИ-инструментах, поэтому каждое ревью
фиксируется в журнале: замечания, балл и вопросы, которые преподаватель
задаст студенту при личной встрече, чтобы проверить понимание сданного.
Журнал накопительный, **по дисциплине**:
`.guap_mcp_tmp/<Дисциплина>/Протокол_<Дисциплина>.xlsx`
(скрипт создаёт файл, папку и шапку сам). В журнале персональные данные
студентов: папка `.guap_mcp_tmp/` в .gitignore — не коммитится и никуда
не отправляется.

### 5.1. Вопросы на понимание (правила)

Формулируются **в момент чтения отчёта** (не отдельным проходом), 3–5 штук:

- каждый привязан к конкретному месту ЕГО отчёта (страница, листинг,
  скриншот, формула) — не обезличенное «расскажите, что делали»;
- типы: «почему сделано так» (объяснение выбора), «что делает этот
  фрагмент» (деталь реализации), «что изменится, если …» (краевой случай),
  «как это связано с условием вашего варианта»;
- прицел — типичные следы ИИ-генеза: необъяснённые константы, шаблонная
  теория вне программы курса, слишком гладкие выводы, конструкции, которые
  на занятиях не давались;
- формулировки нейтральные, для устного задавания. Ограничения на тире из
  раздела 7 на журнал не распространяются — он не на портал.

### 5.2. Записи журнала и рендер

Запись накапливается во время ревью (JSON), пример:

```json
[{"date": "2026-11-10", "subject": "Основы разработки на Dart", "group": "4613МК",
  "student": "Иванов И. И.", "task": "ЛР №3 «Циклы»", "report_id": 12345,
  "max_mark": 10, "complaints": "есть",
  "remarks": "листинг 2 (с. 5): «умные» кавычки, не компилируется",
  "questions": ["с. 5, листинг 2 — почему while, а не for?",
                "что будет при пустом списке?",
                "откуда константа 0.001?"],
  "proposed_mark": 8}]
```

Рендер (список вопросов нумеруется автоматически):

```
uvx --from git+https://github.com/MADTeacher/guap-teacher-mcp guap-teacher protocol append <Протокол.xlsx> <records.json>
```

(команда работает из любого каталога; в клоне репозитория guap-teacher-mcp
то же самое короче — `uv run guap-teacher protocol append ...`)

После рендера показать преподавателю сводную таблицу (студент — претензии —
балл — вопросы кратко) и путь к файлу; файл можно открыть в панели таблиц
(`open_document`). После защиты преподаватель вправе вписать «Балл (итог)»
руками прямо в Excel — `pending` возьмёт итог вместо предв.

### 5.3. Перенос оценок из журнала (в любой, в том числе новой, сессии)

Журнал самодостаточен: в строках есть `report_id`, дисциплина, задание,
оба балла и статус отправки. В новой сессии достаточно самого файла:

1. `uvx --from git+https://github.com/MADTeacher/guap-teacher-mcp guap-teacher protocol pending <Протокол.xlsx>` —
   строки, чей балл ещё не выставлен на портал (при пересдачах побеждает
   последняя проверка; итоговый балл важнее предварительного).
2. Показать преподавателю список (report_id — студент — балл) и получить
   явное согласие: по строке или списком целиком («ставь все по журналу»).
   Нет согласия — нет отправки (раздел 0).
3. Последовательно, без параллельности:
   `grade_report(report_id=..., mark=..., status="принят", comment=...)`
   (правила комментария — раздел 7).
4. После каждой успешной отправки (сверить `after.markPoint`) пометить
   строку: `uvx --from git+https://github.com/MADTeacher/guap-teacher-mcp
   guap-teacher protocol posted <Протокол.xlsx> <report_id>
   --mark <итоговый балл>`.

## 6. Шкала оценивания (ориентир; максимум M из карточки задания)

| Состояние работы | Балл |
|---|---|
| Без замечаний / сверх задания (тесты, защита от краевых случаев) | M или M−1 |
| Мелкие замечания (опечатки в данных, оформление, непроверяемые формулы) | M−1 |
| Некомпилируемый листинг в отчёте или искажённые данные варианта | M−2…M−3 |
| Неполное выполнение | пропорционально невыполненному |

## 7. Комментарий преподавателя (profComment) — ключевое правило

- Комментарий пишем **только если балл понижен более чем на 15% от
  максимума** (для M=10 — при балле ≤ 8; при 9–10 комментарий пустой).
- В комментарии — **только конкретные замечания**, поясняющие понижение:
  что именно и где (задание, страница, листинг).
- **Никаких вопросов в комментарии не пишем** («вопрос на защите» и т.п.) —
  вопросы студенту задаются устно на защите, profComment не для этого.
- **Тире в комментарии — только среднее «–», длинное «—» не используем**
  (стилевое правило владельца). Знак минуса `−` (U+2212) запрещён
  полностью — портал его отклоняет (см. раздел 8); минус пишем обычным
  дефисом `-`.

## 8. Выставление оценки

**Перед вызовом — стоп-проверка:** преподаватель явно согласовал именно этот
балл (и статус) по именно этому отчёту? Нет согласия → возвращаемся к ревью
и вопросу, вызов не делаем.

```
grade_report(report_id=<id>, mark=<балл>, status="принят", comment="<замечания или пусто>")
```

- Статусы: `принят` (обычный итог), `не принят` (тогда комментарий
  обязателен). Отправляется PATCH со свежим CSRF-токеном; в ответе
  `after.markPoint`/`after.status` — фактическое состояние, сверить.
- **Диагностика по редиректу:** `302 → /inside/professor/reports` = успех;
  `302 → на страницу самого отчёта` = ошибка валидации портала, ничего не
  сохранилось (немедленное перечитывание формы может показать «old input» —
  ложные значения; истинное состояние проверять свежим GET).
- **Текст комментария:** тире — среднее «–», не длинное «—» и не минус
  `−` (U+2212). U+2212 отклоняется валидацией портала (проверено
  2026-11-09); «—» и «–» проходят, но по стилю владельца пишем «–».
  Отрицательные числа — с обычным дефисом: `-2`, `-12`.
- Если инструмент недоступен в текущей сессии MCP (сервер не перезагружался
  после добавления `grade_report`) — тот же путь выполняется напрямую:
  `uv run python` + `GuapClient.post_form` + `parse_report_review_form`
  + `resolve_report_status` (см. git-историю / server.py).

## Подводные камни

| Симптом | Причина | Действие |
|---|---|---|
| Дисциплины нет в `list_subjects` | портал отдаёт по 10 дисциплин на страницу (`per_page` игнорируется) | `list_subjects(..., all_pages=True)` (или `page=2, 3, ...`); либо взять id из карточки задания |
| Пустой текст формул в PDF | формулы — картинки | «не проверено по тексту», не штраф |
| Листинг «не скомпилируется» | автозамена Word при вёрстке | замечание −2…−3, попросить исправить |
| `get_report` показал profComment пустым | старый парсер не читал textarea | уже исправлено; смотреть `grade_report.after` |
| POST оценки «прошёл», но ничего не сохранилось | `−` (U+2212) в комментарии | тире → «–», минус → `-`, повторить отправку |
| `protocol` падает с PermissionError | журнал открыт в Excel | попросить преподавателя закрыть файл, повторить |
| `pending` пуст, а оценки не выставлены | журнал другой дисциплины / нет балла в строке | найти файл в `.guap_mcp_tmp/`, проверить балл |
| Дубли строк в расписании/списках | подгруппы | схлопывать одинаковые записи |

## Настройка под себя

Это канонический текст — отправная точка, а не догма. Личная копия
преподавателя: `~/.agents/skills/guap-review/SKILL.md` (создаётся
`guap-teacher init`; каталог переопределяется переменной GUAP_SKILLS_DIR).
Правь её под свои правила приёмки и оценивания — сам или попроси агента
(«титульник не проверяй, зато ругай за отсутствие тестов»); ZCode, Codex
и Qwen Code читают её напрямую. Обновления движка личную копию не
трогают; сравнить с каноном: `guap-teacher skills diff`.
