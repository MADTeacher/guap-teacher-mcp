# Утренняя сводка по отчётам (guap-teacher MCP)

Три read-only запроса к порталу, последовательно. Никаких write-инструментов.

## Шаги

1. `check_auth_status` → если не `"authenticated": true`, ответ сводки —
   одной строкой: «сессия pro.guap.ru истекла, нужен ручной вход
   (authenticate)». Дальше не ходить (автоматически логиниться нельзя —
   вход всегда руками через браузер).
2. `list_reports(status="1", owner="1", per_page=100, filters=["semester", "subject"])`
   — ожидающие проверки мои отчёты. Компактный `filters` обязателен:
   полный `filter_options` (список студентов ~500 записей) обрежет ответ.
3. `list_tasks(per_page=100, filters=[])` — снять дедлайны заданий;
   отобрать 3–5 ближайших `deadline` от сегодня.

## Формат ответа (коротко, markdown)

- «Отчётов ожидает проверки: N» + разбивка по дисциплинам/заданиям
  (сколько по каждому), при 4 и меньше — построчно с ФИО и датой загрузки.
- «Ближайшие дедлайны»: задание — дата (только будущие).
- Ничего больше: без советов, без таблиц на весь экран. Сводка должна
  читаться за 10 секунд.

## Для cron-запуска

Сводка самодостаточна: годится как единственная инструкция запуска по
расписанию. Если сессия умерла — сводка честно сообщает об этом одной
строкой, это нормальный исход, не ошибка.

## Настройка под себя

Это канонический текст — отправная точка, а не догма. Личная копия
преподавателя: `~/.agents/skills/guap-digest/SKILL.md` (создаётся
`guap-teacher init`; каталог переопределяется переменной GUAP_SKILLS_DIR).
Правь её под свои правила приёмки и оценивания — сам или попроси агента
(«титульник не проверяй, зато ругай за отсутствие тестов»); ZCode, Codex
и Qwen Code читают её напрямую. Обновления движка личную копию не
трогают; сравнить с каноном: `guap-teacher skills diff`.
