# Заполнение официальной ведомости (guap-teacher MCP)

Навык переносит итоговые баллы группы с портала в официальную ведомость
преподавателя (xlsx) по заданным диапазонам. Все запросы к порталу —
read-only GET, последовательно.

## 0. ГЛАВНОЕ ПРАВИЛО: ведомость на портал не отправляется

> **Выгрузка/отправка заполненной ведомости куда-либо (портал, почта,
> сторонний сервис) — ТОЛЬКО ВРУЧНУЮ самим преподавателем.** Агент никогда
> не выгружает, не отправляет и не «публикует» ведомость. Результат работы —
> локальный файл, передаваемый преподавателю. Единственные write-инструменты
> сервера — grade_report, edit_task, create_material; к ведомости они
> отношения не имеют и не используются.

## 1. Входные данные (уточнить у преподавателя)

1. **Путь к официальному файлу ведомости** (xlsx от института/кафедры).
2. **Дисциплина** (id или название — разрешается п.2).
3. **Группа(ы)**, входящие в ведомость.
4. **Диапазоны баллов → оценка**, например:
   «8–10 → зачтено, 0–7 → не зачтено» или
   «9–10 → отл, 7–8 → хор, 5–6 → удовл, ниже — неуд».
   Диапазоны задаёт преподаватель в явном виде — шкалу не выдумывать.
5. Какую величину брать за основу: `total_mark` (итог по дисциплине) —
   по умолчанию; если преподаватель просит по конкретному заданию —
   соответствующий элемент `marks` (столбец `task_columns`).

## 2. Предусловие и разрешение id

1. `check_auth_status` → `"authenticated": true`? Если нет — `authenticate`
   и повторить.
2. `subject_id`: `list_subjects` по названию; если дисциплина не находится —
   `get_task` любого её задания → `subject_id`.
3. `group_id`: `get_subject(subject_id)` → `groups` (id + имена + ссылки на
   ведомости). Берите id оттуда, не выдумывайте.

## 3. Выгрузка данных

- `get_group_grades(subject_id, group_id)` по каждой группе **последовательно**
  (один вызов — один запрос к порталу, без параллельности).
- В ответе: `rows` — `{name: «Фамилия И. О.», marks: [{task, status, mark}],
  total_mark, total_max}`.
- Студенты с `total_mark = 0` или `null` (ничего не сдано) — **оценку не
  проставлять**, собрать в отдельный список для преподавателя.

## 4. Сопоставление ФИО

- В данных портала ФИО краткие («Иванов И. О.»), в официальной ведомости
  обычно полные («Иванов Иван Олегович») — нормализовать: фамилия целиком +
  инициалы, ё→е, лишние пробелы.
- Сначала прочитать листы официальной ведомости (плагин xlsx), найти
  столбец с ФИО и столбец(ы) для оценки — структуру не угадывать: если
  столбцы не очевидны, спросить преподавателя.
- Сопоставление однозначное (ровно одна фам.; инициалы совпали) — заполнять.
- Неоднозначное или ненайденное — **не заполнять молча**: собрать список
  «не сопоставлено» и показать преподавателю.

## 5. Заполнение файла

- Работать через навык `xlsx` (openpyxl); оригинал **не перезаписывать**:
  результат сохранить рядом как `<имя>_заполненный.xlsx`.
- Вписывать только оценки по диапазонам из п.1; формат значения — как в
  соседних заполненных ячейках ведомости (если есть образец).

## 6. Отчёт преподавателю

1. Путь к заполненному файлу.
2. Сколько оценок проставлено, по какой шкале.
3. Списки: без оценки (не сдавали), не сопоставленные ФИО.
4. Напоминание: выгрузка ведомости — вручную.

## Настройка под себя

Это канонический текст — отправная точка, а не догма. Личная копия
преподавателя: `~/.agents/skills/guap-vedomost/SKILL.md` (создаётся
`guap-teacher init`; каталог переопределяется переменной GUAP_SKILLS_DIR).
Правь её под свои правила приёмки и оценивания — сам или попроси агента
(«титульник не проверяй, зато ругай за отсутствие тестов»); ZCode, Codex
и Qwen Code читают её напрямую. Обновления движка личную копию не
трогают; сравнить с каноном: `guap-teacher skills diff`.
