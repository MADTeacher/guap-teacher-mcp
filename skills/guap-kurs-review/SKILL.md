# Проверка курсовых работ (guap-teacher MCP)

Навык — специфика курсовых (пояснительная записка к курсовой работе или
проекту). Общий конвейер проверки — живая сессия, поиск отчётов по
дисциплине, скачивание PDF, шкала оценивания, правила profComment,
`grade_report` и диагностика по редиректу — описан в навыке **guap-review**
(`skill://guap-review`, файл `skills/guap-review/SKILL.md`): прочитай его
перед первой проверкой курсовых. Здесь — только отличия и дополнения.
Все шаги последовательные, без параллельных запросов к порталу.

## 0. Главное правило (дублируется намеренно)

> **Оценка ставится ТОЛЬКО с явного согласия преподавателя.** Без
> подтверждённого «ставь»/«соглас» на конкретный балл по конкретной работе —
> ничего не отправляем. `grade_report` — единственный write-инструмент;
> порядок: ревью с предложенным баллом → явное добро → отправка → сверка
> `after.markPoint`/`after.status`.

## 1. Предусловие: живая сессия

1. `check_auth_status` → `"authenticated": true`? Если нет — `authenticate`
   и повторить проверку.

## 2. Найти курсовые задания и их отчёты

- `list_tasks(type=<курсовая>)`: точное значение типа — из `filter_options`
  ответа `list_tasks` (типы: лабораторные, практика, курсовая...). В карточке
  `get_task` — тема/описание, макс. баллы (M шкалы), предельная дата.
- Нужной дисциплины может не быть в `list_subjects` — тогда `subject_id`
  берём из ссылки `/inside/subjects/{id}` в ответе `get_task` (нюанс из
  guap-review).
- Отчёты: `list_reports(subject=<id>, per_page=100)`; ожидающие — статус
  «ожидает проверки» (фильтр статуса `1`).
- Курсовые часто сдаются по этапам — если присланный объём похож на часть
  ПЗ, уточнить у преподавателя, полный это текст или промежуточный отчёт,
  прежде чем оценивать как целую работу.

## 3. Скачать и открыть

Как в guap-review: `download_report(report_id,
save_dir=<workspace>/.guap_mcp_tmp/<Дисциплина>)` — дефолтный каталог
скачивания сервера и так внутри workspace; PDF-панель ZCode принимает
только пути внутри workspace, открываем `open_document` + `read_document`,
после ревью папку удаляем. Пояснительная записка объёмная — читать
постранично с `cursor`.

## 4. Ревью содержания пояснительной записки

Эталонная структура (по официальному примеру ГУАП `sample_kurs.docx`):
титульный лист → СОДЕРЖАНИЕ → ВВЕДЕНИЕ → разделы 1..N → ЗАКЛЮЧЕНИЕ →
СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ → ПРИЛОЖЕНИЯ (А, Б, …).

- **Соответствие заданию:** тема и требуемые результаты — из `get_task`;
  всё заявленное в задании выполнено и показано в ПЗ.
- **Введение:** есть актуальность, цель и задачи; задачи должны
  покрываться разделами основной части (по задаче на раздел — типовая
  схема).
- **Заключение:** выводы по каждой задаче введения; не противоречит
  содержимому и не обещает несделанного.
- **Источники:** по теме работы (не фиктивный набор), описание по
  ГОСТ Р 7.0.100-2018, в тексте есть ссылки на номера источников.
- **Код и материалы:** вынесены в приложения, на каждое приложение есть
  ссылка в тексте. Листинги в приложениях проверять как в guap-review
  (компилируемость, «умные» кавычки, регистр переменных, данные варианта).
- **Формулы-картинки** (пустой текстовый слой) — «не проверено по тексту»,
  ошибкой студента не считать.
- **Протокол проверки** (журнал + вопросы на понимание) — режим навыка
  guap-review (его раздел 5): применяется и к курсовым, в поле `task`
  пишем «Курсовая: <тема>».

## 5. Оформление курсовой по правилам ГУАП

Общие правила текста (Times New Roman ≥12 пт / 14 пт, по ширине, отступ
1,25 см, интервал 1,5), заголовков, нумерации страниц, рисунков, таблиц,
приложений и списка источников — те же, что для лабораторных: раздел
«Оформление лабораторных работ» навыка guap-review. Источник правил —
<https://guap.ru/regdocs/docs/uch>. Специфика курсовой:

- **Титульный лист по бланку**
  <https://fs.guap.ru/regdocs/2023/uch/titl/kurs.docx> (институты 1–4,
  ФПТИ, факультет 6, ВУЦ, ФДПО; бланки института 8 не используем):
  «КУРСОВАЯ РАБОТА (ПРОЕКТ) ЗАЩИЩЕНА С ОЦЕНКОЙ» + блок «РУКОВОДИТЕЛЬ»
  (должность, уч. степень, звание | подпись, дата | инициалы, фамилия);
  «ПОЯСНИТЕЛЬНАЯ ЗАПИСКА К КУРСОВОЙ РАБОТЕ», тема работы, «по дисциплине:
  …»; блок «РАБОТУ ВЫПОЛНИЛ» / «СТУДЕНТ ГР. № …»; внизу «Санкт-Петербург
  20__».
- **Содержание:** после каждого заголовка — отточие и номер страницы;
  подразделы с отступом 2 знака от обозначения разделов, пункты — 4;
  в содержании — введение, все разделы и подразделы, заключение, список
  источников, приложения с номерами страниц начала.
- Титульный лист, содержание и каждый раздел основной части — с новой
  страницы; на титульном листе номер страницы не ставится.
- Эталон вёрстки — официальные шаблоны Word: Ш-1 (титульные листы,
  включая пояснительную записку к курсовой) и Ш-2 (комментированный
  пример текстовой части), руководство:
  <https://fs.guap.ru/regdocs/2025/shablon/instr_shab.docx>.

## 6. Шкала и комментарий преподавателя

- Шкала — как в guap-review (M; M−1 мелкие замечания; M−2…M−3
  существенные; неполное выполнение — пропорционально). Для курсовой
  существенные: тема не раскрыта, отсутствуют обязательные разделы,
  заключение не соответствует задачам введения.
- profComment: только при понижении более чем на 15% от M; только
  конкретные замечания (раздел, страница); без вопросов студенту; тире —
  среднее «–», минус — обычный дефис `-` (U+2212 портал отклоняет).

## Подводные камни

| Симптом | Причина | Действие |
|---|---|---|
| Дисциплины нет в `list_subjects` | портал отдаёт не все предметы | `subject_id` из `get_task` |
| Прислана часть ПЗ | курсовая сдаётся по этапам | уточнить у преподавателя, полный ли текст |
| Длинная PDF обрезается | ПЗ объёмная | `read_document` постранично с `cursor` |
| Формулы/текст недоступны | картинки вместо текста | «не проверено по тексту», не штраф |
| Код только в приложениях | так и задумано | проверять листинги приложений, не пропуская |
