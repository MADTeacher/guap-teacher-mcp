# Быстрое получение расписания (guap-teacher MCP)

Операция снимает расписание преподавателя за произвольный период через
инструменты MCP-сервера `guap-teacher`, не открывая браузер. Все шаги —
только read-only GET-запросы, последовательно, без параллельности.

## 0. Предусловие: живая сессия

1. `check_auth_status` → `"authenticated": true`? Если нет — `authenticate`
   (вход руками в открывшемся браузере) и повторите проверку.

## 1. Id преподавателя в фильтре расписания

Фильтр `teacher` у портала принимает **только числовой id из отдельного
пространства значений** (id профиля /inside/profile/{id} не подходит):

- без фильтра group/teacher таблица всегда пустая («Все» не разворачивается);
- передача ФИО строкой → HTTP 500.

**Быстрый путь (владелец репозитория):** Чернышев С.А. → `teacher=157`
(проверено 2026-11-09, сборка расписания от 05.11.2026). Первая же выкачанная
неделя с занятиями должна содержать «Чернышев С.А.» в ячейках — если нет,
id устарел, разрешите заново:

**Разрешение неизвестного id (универсально):** запросить только фильтр
`teacher` — компактный ответ без гигантского списка групп:

```
get_schedule(view="day", date_iso=<любая дата ГГГГ-ММ-ДД>, filters=["teacher"])
```

В `filter_options.teacher` найти Фамилию (`value` — искомый id, подпись
вида «Чернышев С.А. (доцент, канд. техн. наук)»). Параметр `filters`
(список имён / `[]`) доступен во всех списковых инструментах и спасает
ответы от обрезания.

## 2. Выкачка периода

Период = набор ISO-недель; вызывать `get_schedule(view="week", iso_year=Y,
iso_week=N, teacher=<id>)` **последовательно**, по одному запросу за раз:

- месяц → ISO-недели, покрывающие его дни (например, декабрь 2026 = W49–W53);
- в ответе `headers` дают даты дней («Пн - 30.11»), `rows` — пары; пустая
  сетка = занятий на неделе нет;
- если неделя вернула HTTP 404 (бывает на хвосте года: `/week/2026/53`) —
  добрать оставшиеся дни по одному через `view="day", date_iso=...`;
- дни вне запрошенного периода из граничных недель просто отбросить.

Дубли: каждая пара в `rows` идёт двумя строками (подгруппы) — при выводе
схлопывать одинаковые `pair`+`time`+`text`.

## 3. Разбор ячейки

Формат текста ячейки:
`<Пр|Л> <Дисциплина> <ФИО (должность, степень)> <группы через пробел> <Адрес>, <ауд.>`

Пример: `Пр Основы проектной деятельности в профессии Чернышев С.А. (доцент,
канд. техн. наук) 4618 Б.Морская 67 лит.А, 53-09` → вид=практика, группа=4618,
корпус=Б.Морская 67 лит.А, аудитория=53-09.

Ячейки `rows` идут в ответе **до** `filter_options` (огромного списка групп),
поэтому переживают обрезку больших ответов — не пугайтесь truncation в конце.

## 4. Формат вывода

Markdown-таблица по неделям: `| Дата | Время | Вид · Дисциплина | Группа | Ауд. |`,
после таблиц — короткая сводка (итого занятий, disciplines, последний день
занятий). Дни/недели без занятий указывать одной строкой «занятий нет».

## Подводные камни (кратко)

| Симптом | Причина | Действие |
|---|---|---|
| Пустая таблица | нет фильтра teacher/group | передать `teacher=<id>` |
| HTTP 500 | в `teacher` передана строка (ФИО) | только числовой id |
| HTTP 404 на неделе | нет такой недели в базе (напр. W53) | добрать дни через `view="day"` |
| Ответ обрезан | огромный `filter_options` в хвосте | передавать `filters=["teacher"]` или `filters=[]` |

## Настройка под себя

Это канонический текст — отправная точка, а не догма. Личная копия
преподавателя: `~/.agents/skills/guap-schedule/SKILL.md` (создаётся
`guap-teacher init`; каталог переопределяется переменной GUAP_SKILLS_DIR).
Правь её под свои правила приёмки и оценивания — сам или попроси агента
(«титульник не проверяй, зато ругай за отсутствие тестов»); ZCode, Codex
и Qwen Code читают её напрямую. Обновления движка личную копию не
трогают; сравнить с каноном: `guap-teacher skills diff`.
