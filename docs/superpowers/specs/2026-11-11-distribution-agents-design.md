# Дизайн: распространение guap-teacher между преподавателями (модель `.agents`)

- Дата: 2026-11-11
- Статус: согласован с владельцем в ходе бреншторминга 2026-11-10/11,
  ожидает ревью спеки
- Затрагивает: `src/guap_teacher_mcp/skills.py`, точку входа `guap-teacher`
  (`pyproject.toml`), упаковку пакета (package data), README; отдельный
  репозиторий `guap-teacher-plugin` (фаза 2)

## Контекст

Система двухслойна по построению: MCP-сервер (движок: парсеры портала,
безопасность, write-инструменты) и агентские навыки (методология:
чек-листы ревью, правила приёмки, критерии оценивания, порядок выставления
оценок). Сегодня навыки лежат в репозитории сервера и несут личную
методологию автора. Задача — раздать систему преподавателям так, чтобы
каждый выстроил **собственное** видение приёмки и оценивания, не теряя при
этом обновлений движка при изменениях вёрстки портала.

## Решения владельца

| Вопрос | Решение |
|---|---|
| Аудитория | Смесь: ядро — технари с агентами; не-технарь ставит систему и настраивает её «разговором» со своим агентом |
| Глубина кастомизации | Одно личное видение на преподавателя; без профилей по дисциплинам |
| Границы правок | Полная свобода: копия преподавателя — его зона ответственности; жёсткие пределы остаются только техническими (чего нет в коде сервера, того нет) |
| Обратный поток | Односторонняя раздача; каталога сообщества и приёма PR нет |
| Claude Code | Исключён из поддержки: не читает `.agents/skills`; вся работа строится вокруг `.agents` |
| Плагин ZCode | Отдельный репозиторий `guap-teacher-plugin` (фаза 2) |

## Факт-база: поддержка `~/.agents/skills` (проверено 2026-11-10)

| Харнесс | Поддержка | Первоисточник |
|---|---|---|
| Codex | ✅ родной каталог: `~/.agents/skills` + `.agents/skills` от cwd вверх до корня репо | learn.chatgpt.com/docs/build-skills |
| Qwen Code | ✅ shared-каталог (`~/.agents/skills`, `.agents/skills`); при конфликте имён выигрывает `.qwen/skills` | QwenLM/qwen-code docs/users/features/skills.md |
| ZCode | ✅ читает `~/.agents/skills` (подтверждено на машине владельца) | локально |
| Claude Code | ❌ только `.claude/skills`, `~/.claude/skills`, плагины; запрос поддержки — anthropics/claude-code#31005 | code.claude.com/docs/en/skills, CHANGELOG |

Спека agentskills.io закрепляет формат SKILL.md (файл), но не пути
обнаружения — конвенция `.agents` сложилась де-факто; строимся на ней.

## Архитектура: два слоя

```
Слой 1. ДВИЖОК — uv-пакет (uvx из git+https, без clone)
        MCP-сервер + канонические навыки внутри пакета как данные.
        Обновляется от автора. Навыков не «исполняет», только раздаёт.

Слой 2. ~/.agents/skills/guap-*/SKILL.md — ЛИЧНЫЕ КОПИИ ПРЕПОДАВАТЕЛЯ
        Единственное место методологии. Родной каталог ZCode, Codex,
        Qwen Code — читается харнессами напрямую, без посредников.
        Правится преподавателем как угодно (рукой или через агента).
        Обновление движка эти файлы не трогает никогда.
```

Стабов-указателей, реестра харнессов и симлинков нет: всё, что читает
`.agents`, работает само; что не читает (Claude Code) — вне области
поддержки.

## Механика

### Точка входа: подкоманды

`guap-teacher` без аргументов — как сейчас, старт MCP-сервера (stdio);
MCP-конфиги действующих установок не меняются.

- `guap-teacher init [--skills-dir <path>]` — установка/досеивание;
- `guap-teacher skills diff` — read-only сравнение личных копий с каноном
  текущей версии пакета.

### `init`

1. Сеет навыки из канона пакета в личный каталог (по умолчанию
   `~/.agents/skills`, override — `GUAP_SKILLS_DIR` или `--skills-dir`).
   **Существующие файлы никогда не перезаписывает** — идемпотентен,
   повторный запуск доустанавливает только отсутствующие (в т.ч. новые
   навыки, появившиеся в каноне).
2. Печатает сниппеты MCP-конфига (ZCode, Codex, Qwen) с командой запуска
   `uvx --from git+https://github.com/MADTeacher/guap-teacher-mcp guap-teacher`.
3. Печатает сводку: что посеяно, что пропущено (уже существует), куда.

### `skills diff`

Для каждого канонического имени: `identical` / `differs` (личная копия
отличается от канона — это норма, информация к размышлению) /
`missing` (в каноне появился навык, которого нет в личном каталоге —
`init` доустановит). Авто-мерджа нет и не будет: односторонняя раздача,
перенос находок из канона — осознанное решение преподавателя (или его
агента по фразе «покажи, что нового в каноне»).

### Загрузчик `skills.py`

- Два корня: личный (`~/.agents/skills`, override `GUAP_SKILLS_DIR`) и
  канонический (package data внутри пакета — `skills/` репозитория едет в
  wheel).
- Разрешение: при совпадении имени **личный побеждает** (переопределение
  навыка целиком, без мерджа).
- В ресурсы `skill://` попадают **только имена канона** — прочие личные
  навыки преподавателя (не `guap-*` из канона) сервер не подхватывает.
- `skill://index`, `skill://<имя>` и mime-типы не меняются.
- Семантика `GUAP_SKILLS_DIR` меняется: раньше — полная замена каталога
  навыков, теперь — override личного корня (канон всегда из пакета).

### Упаковка

Канонический `skills/` включается в dist как package data (настройка
build-backend в `pyproject.toml`); установка движка —
`uvx --from git+https://github.com/MADTeacher/guap-teacher-mcp`. Публикация
на PyPI — вне scope (пересмотр позже, git+https достаточно).

## Обновления

- **Сломалась вёрстка портала** → автор чинит парсер → преподаватель
  обновляет движок: `uvx --refresh --from git+...` или просто просит
  своего агента «обнови guap-teacher». Личные навыки в другом месте —
  конфликт невозможен.
- **Автор улучшил канонический навык** → личные копии не трогаются;
  увидеть изменения — `guap-teacher skills diff`.
- **Новый канонический навык** → повторный `init` доустанавливает только
  отсутствующие.

## Траектории установки

- **Технарь**: `uvx --from git+... guap-teacher init` → сниппет из stdout →
  свой MCP-конфиг → готово.
- **Не-технарь без git**: пишет своему агенту «поставь guap-teacher, вот
  ссылка». README пишется **агент-читаемым** (пошаговая инструкция для
  агента): агент сам выполняет uvx-команду и сам знает формат
  MCP-конфига своего харнесса. Пер-харнесс установщики не нужны —
  установщик уже сидит у преподавателя в терминале.
- **Настройка под себя**: разговор с агентом («титульник не проверяй,
  ругай за отсутствие тестов») → агент правит
  `~/.agents/skills/guap-review/SKILL.md`. Каждый канонический навык
  получает короткий раздел «Настройка под себя» с путём до личной копии —
  навык сам объясняет агенту, где его править.

## Плагин ZCode (фаза 2, отдельный репозиторий)

Репозиторий: `C:\Users\MADTeacher\Documents\GitHub\guap-teacher-plugin`
(создан 2026-11-11). Назначение — установка «в один клик» для ZCode:

- внутри плагина: только подключение MCP-сервера (команда uvx) и
  agent-readable onboarding с инструкцией выполнить `init`;
- **навыков внутри плагина нет** — иначе дублирование с
  `~/.agents/skills` и непредсказуемый приоритет хоста; после `init`
  ZCode подхватывает навыки нативно.

## Тестирование

Только офлайн-фикстуры (правила AGENTS.md), без сети:

- разрешение двух корней: личный побеждает, не-канонические имена из
  личного каталога игнорируются, отсутствие личного корня — канон;
- идемпотентность `init` на tmp-каталоге: существующие не перезаписывает,
  отсутствующие доустанавливает;
- `skills diff`: identical / differs / missing;
- предкоммит: `uv run pytest` зелёные,
  `uv run python -c "import guap_teacher_mcp.server"` без ошибок.

## Отклонённые альтернативы

- **Fork-модель** (правки `skills/` в клоне + `git pull`) — конфликты на
  каждом обновлении, тупик для не-технаря.
- **Стабы-указатели в пер-харнесс каталоги** — не нужны: выбранная
  аудитория читает `.agents` нативно; исключение (Claude Code) исключено
  решением владельца.
- **Симлинки** `.claude/skills` → `.agents/skills` — тихо ломаются на
  Windows.
- **«Конституция» / защищённый слой инвариантов** — отклонено: полная
  свобода правок, копия преподавателя — его зона ответственности.
- **Каталог сообщества / приём PR** — отклонено: односторонняя раздача.
- **Авто-мердж канона в личные копии** — отклонено: видение преподавателя
  свято, обновление канона — только через осознанный `skills diff`.
