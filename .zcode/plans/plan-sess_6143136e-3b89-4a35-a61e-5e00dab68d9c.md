# План: агентский навык «быстрое расписание» + Skills over MCP

## Context

В прошлой сессии мы получили расписание преподавателя за декабрь через MCP-инструменты `guap-teacher`: выяснили, что (1) без фильтра group/teacher портал возвращает пустую таблицу, (2) фильтр `teacher` принимает только числовой id своего пространства значений (по ФИО — HTTP 500), (3) id надёжно извлекается из HTML страницы расписания (`<option value="157">Чернышев С.А.`), (4) период выкачивается ISO-неделями, а неделя 53 может отдать 404. Задача — оформить этот опыт как **агентский навык в каталоге `skills/`** репозитория и **обеспечить поддержку Skills over MCP** на стороне сервера; на стороне ZCode — проверить и обеспечить фактическую доступность навыка.

Факты из исследования:
- Сервер: официальный `mcp` SDK **2.3.0**, v2 API `MCPServer` (`server.py:19,26`), 15 инструментов, ресурсов/промптов сейчас нет. Декоратор `@mcp.resource(uri, name=…, mime_type=…)` и `add_resource()` есть в установленном SDK (server.py SDK:788) — поддержка добавляется без новых зависимостей.
- ZCode: **Skills over MCP хостом не поддерживается** (в гайдах zcode-guide, конфиг-схеме и бандле приложения нет `skill://`/`skills/list`; MCP-серверы дают только инструменты). Навыки ZCode обнаруживает только на диске: `~/.zcode/skills`, `~/.agents/skills`, **`<repo>/.zcode/skills`**, `<repo>/.agents/skills`, плагины (диагностика-skills, zcode-configuration-guide).
- Тесты репозитория: офлайн, inline-HTML фикстуры, чистые функции; сетевого кода в тестах нет.

## Изменения

### 1. Канонический навык — `skills/guap-schedule/SKILL.md` (новый каталог)

Frontmatter: `name: guap-schedule`, `description:` (рус., когда применять — «моё расписание», месяц/неделя/день с pro.guap.ru). Содержимое — воспроизводимая операция:

1. **Быстрый путь**: владелец репозитория — Чернышев С.А., id `157` (проверено 2026-11-09); первая же выкачанная неделя должна содержать «Чернышев С.А.» в ячейках — иначе id устарел, перейти к п.2.
2. **Разрешение неизвестного id**: без фильтра — пусто; по ФИО — HTTP 500; `get_page` показывает только подписи без value; надёжный способ — `download_url("/inside/students/classes/schedule/day/<дата>")` → локальный grep `<option value="(\d+)"[^>]*>Фамилия` по сохранённому файлу.
3. **Выкачка периода**: ISO-недели последовательно, `view=week&teacher=<id>`; хвостовые дни при 404 на неделе (случай `/week/2026/53`) — через `view=day`. Без параллельных запросов (правила AGENTS.md).
4. **Разбор ячейки**: формат `Пр|Л Дисциплина ФИО (должность, степень) Группы(через пробел) Адрес, ауд.`; rows идут до `filter_options`, поэтому переживают обрезку ответа.
5. **Формат вывода**: markdown-таблицы по неделям.

### 2. Загрузчик + регистрация ресурсов — `src/guap_teacher_mcp/skills.py` (новый модуль)

- `load_skills(root: Path) -> list[Skill]` — чистая функция: сканирует `root/*/SKILL.md`, возвращает `(name, markdown)` по имени каталога; пропуски/отсутствие каталога — пустой список (тестируемо офлайн).
- `register_skill_resources(server: MCPServer, root: Path) -> int` — регистрирует в MCPServer:
  - статический индекс `skill://` (список доступных навыков, `text/markdown`);
  - по одному статическому ресурсу `skill://{name}` на навык (контент SKILL.md, `text/markdown`, name/description из каталога);
  - защита от late-binding в замыкании (default-аргумент);
  - возвращает число зарегистрированных навыков.

### 3. Включение в сервер — `src/guap_teacher_mcp/server.py`

Импорт `skills.py`; после определений инструментов — вызов `register_skill_resources(mcp, _skills_root())`, где корень = `Path(__file__).parents[2] / "skills"` с переопределением через env `GUAP_SKILLS_DIR` (в стиле `GUAP_SESSION_PATH`); молчаливый no-op, если каталога нет. Инструменты не трогаем — только ресурсы, read-only.

### 4. Доступность в ZCode — `.zcode/skills/guap-schedule/SKILL.md` (новый)

Так как ZCode не забирает навыки из MCP, кладём тонкий стаб с тем же frontmatter (name/description), тело: «полная инструкция — прочитай `skills/guap-schedule/SKILL.md` в корне репозитория и следуй ей». Один источник истины остаётся в `skills/`; ZCode подхватит стаб при старте новой сессии (workspace-уровень `.zcode/skills`).

### 5. Тесты — `tests/test_skills.py` (новый, офлайн)

По образцу `tests/test_pages.py` (без сети):
- `load_skills`: happy path на `tmp_path` (два навыка, порядок), отсутствие каталога → `[]`, каталог без SKILL.md пропускается;
- регистрация: свежий `MCPServer("test")` + `register_skill_resources(...)` → в менеджере ресурсов есть `skill://` и `skill://guap-schedule`; повторный вызов не падает;
- (усиление, если API позволит без хаков) in-memory интеграционный тест через `mcp.shared.memory.create_client_server_memory_streams` + `ClientSession.list_resources()/read_resource()` — настоящий e2e Skills over MCP без сети; при трении API — достаточно проверки менеджера.

### 6. Документация

- `README.md`: раздел «Агентские навыки (Skills over MCP)» — канонический каталог `skills/`, экспозиция через ресурсы `skill://`, честная оговорка: ZCode пока не потребляет навыки из MCP → локальный стаб в `.zcode/skills/`; как добавить новый навык.
- `AGENTS.md`: в карту структуры добавить `skills/` и `skills.py`.

Зависимости/`pyproject.toml` не меняются (mcp 2.3.0 уже умеет ресурсы).

## Верификация

1. `uv run pytest` — все тесты зелёные (включая новые офлайн-тесты навыков).
2. `uv run python -c "import guap_teacher_mcp.server"` — pre-commit проверка AGENTS.md проходит; регистрация ресурсов не падает без/при наличии `skills/`.
3. Смок Skills over MCP: офлайн-скрипт (uv run python) печатает зарегистрированные `skill://`-ресурсы и контент `skill://guap-schedule`.
4. Итоговый ответ пользователю: сервер — поддержка добавлена и проверена; ZCode — хостом Skills over MCP **не поддерживается** (подтверждено по гайдам/бандлу), навык доступен ZCode через локальный `.zcode/skills/` (появится в списке навыков новой сессии).
