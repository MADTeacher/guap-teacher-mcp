# План: расширение guap-teacher-mcp (ведомость, профили, write-операции)

## Context

Анализ (2026-11-10, живая сессия) показал: сервер покрывает ~половину преподавательского кабинета. Решения владельца: объявления — не берём; создание отчёта за студента (`reports/{task}/{student}/create`) — исключено полностью (в коде его и нет; в выводы парсеров эти ссылки не попадают); ведомость — скачивание данных с портала + навык заполнения официального xlsx по диапазонам баллов, **загрузка обратно — только вручную, никогда**; остальное из списка дефицитов — реализуем.

Разведанные факты:
- **Ведомость** = `GET /inside/groups/{subject_id}/{group_id}` «Список группы»: чистая таблица (ФИО кратко, статус+балл по каждому заданию, «Итого N из M»), без меню.
- **Профиль студента** `/inside/profile/{id}`: ФИО, институт, группа, студбилет, специальность, форма обучения, статус, приказ, email.
- **Карточка задания** `/show`: h5-поля + таблица отчётов по студентам; несдавшие отличимы по ссылкам `create` (в вывод не включаем — только список ФИО).
- **Форма редактирования задания** `/inside/professor/tasks/{sem}/{id}/edit`: дедлайн, «Открыть для просмотра студентами», «Запретить загружать после предельной даты», макс. балл и т.д.
- **Форма материала** `/inside/professor/materials/create`: название, семестр, дисциплина, группы, видимость, «оповестить по почте», внешняя ссылка **или** файл (multipart, ≤8 МБ).
- `filter_options` разносит ответы (list_reports ~200 КБ из-за фильтра student на ~500 записей).

## Шаг 0. Снять фикстуры (пока жива сессия!)

`download_url` в временную папку, затем перенести в `tests/fixtures/` и встроить в тесты:
1. `/inside/profile/56341` (профиль студента)
2. `/inside/professor/tasks/187688/show` (карточка задания)
3. `/inside/groups/3446314/7844` (список группы)
4. `/inside/professor/tasks/28/187688/edit` (форма задания)
5. `/inside/professor/materials/create` (форма материала)

В фикстурах ищем при имплементации: точные `name=` полей, `_method`, значения checkbox, формат даты, action формы.

## Шаг 1. `pages.py` — чистые парсеры (+ тесты на инлайн-фикстурах, стиль `tests/test_pages.py`)

- `parse_filter_options(html, only: list[str] | None = None)` — фильтрация по именам селектов (None = все, как сейчас).
- `parse_student_profile(html)` → `{name, fields{...}, email, achievements}` (имя — `h3.text-center`, поля — h5 «Ключ: значение» по образцу `parse_h5_card`).
- `parse_task_card(html)` → `{title, fields, subject_id, reports: [{student, student_id, report_id, status_text, mark, max}], not_submitted: [{student, student_id}], manage: {edit_url, remove_url}}`. Ссылки `create` в вывод **не** попадают.
- `parse_group_grades(html)` → `{group, task_columns: [...], rows: [{name, marks: [{task, status, mark}], total, total_max}]}`.
- `parse_form_fields(html, action_re)` — обобщение `parse_report_review_form`: любой формы по regex action; отчётная форма переводится на неё.

## Шаг 2. `client.py`

`post_multipart(path, data, files)` — httpx `files=`, Referer как в `post_form`, без follow_redirects.

## Шаг 3. `server.py` — инструменты

**Read:**
- `filters: list[str] | None = None` в `list_reports`, `list_tasks`, `list_materials`, `get_schedule` (None — как сейчас; список — только названные; `[]` — без `filter_options`). Решает обрезание ответов и добывание teacher-id для расписания.
- `get_student(student_id)` — GET `/inside/profile/{id}` + `parse_student_profile`.
- `get_task` — переключить на `parse_task_card` (ключи `title`/`fields` остаются; `links` убрать — все нужные ссылки теперь структурные).
- `get_group_grades(subject_id, group_id)` — GET `/inside/groups/{s}/{g}` + `parse_group_grades`. В docstring: id групп — из карточки дисциплины (`get_subject`) или filter_options отчётов.

**Write (по явному решению владельца 2026-11-10; паттерн grade_report: GET формы → CSRF → POST → перечитать и сверить):**
- `edit_task(task_id, deadline=None, visible=None, forbid_late=None)` — сам находит edit-url через `/show`, оверлеит только переданные поля, остальное из формы не трогает. Осторожно с checkbox (невключённые в Laravel не отправляются).
- `create_material(name, subject, groups, file_path=None, url=None, visible=True, notify=False, semester=None)` — ровно один из `file_path`/`url`; проверка размера ≤8 МБ; multipart через `post_multipart`; semester по умолчанию — выбранный в форме.

В docstrings обоих: меняют данные на портале; в навыках — правило «только с явного согласия преподавателя», как у grade_report.

## Шаг 4. Навыки (`skills/` + стабы `.zcode/skills/`)

- **`guap-vedomost`** (новый): вход — путь официального xlsx + предмет + группа(ы) + диапазоны (например «8–10 → зачтено»); шаги — `get_subject`/`list_subjects` → id; `get_group_grades` по группам последовательно; сопоставление ФИО (полные из filter_options отчётов ↔ краткие «Иванов И. И.» из ведомости и листа); заполнение xlsx (плагин xlsx), результат — `<имя>_заполненный.xlsx` рядом с оригиналом; несопоставленные ФИО — явный список преподавателю, не угадывать. **ЖИРНОЕ правило: выгрузка/отправка ведомости куда-либо — только вручную; агент никогда.**
- **`guap-review`** (правка): шаг 3 — скачивать `download_report(save_dir=<workspace>/.review_tmp)` напрямую, без копирования из ~/Downloads.
- **`guap-schedule`** (правка): раздел «разрешение id преподавателя» заменить на `get_schedule(view="week", filters=["teacher"])` — без download+grep.
- **`guap-digest`** (новый, маленький): утренняя сводка — check_auth_status → list_reports(status="1", filters=["semester","subject"]) + ближайшие дедлайны из list_tasks(filters=[]) → короткий markdown. Приложим к cron-автоматизации по желанию пользователя (создаётся отдельно, с его подтверждения).

## Верификация

1. `uv run pytest` — все парсеры покрыты офлайн-фикстурами, зелёные.
2. `uv run python -c "import guap_teacher_mcp.server"` — без ошибок.
3. Живой smoke (сессия): `get_student(56341)`, `get_task(187688)` (матрица + несдавшие), `get_group_grades(3446314, 7844)`, `list_reports(filters=[])` — компактный ответ.
4. Write-инструменты: живая проверка **только с явного согласия** — `edit_task`: снять текущий дедлайн задания → изменить → сверить → вернуть обратно; `create_material`: создать материал с `visible=False` (студентам не виден); удаление — вручную в интерфейсе портала.
5. Финал: перезапуск MCP-клиента, проверка новых инструментов в списке.
