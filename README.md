# guap-teacher-mcp

MCP-сервер для автоматизации работы преподавателя с [pro.guap.ru](https://pro.guap.ru)
(Личный кабинет ГУАП): список заданий, отчёты студентов, материалы.

Публичного API у портала нет, поэтому сервер работает через сессию браузера:
один вход руками через SSO → cookie → аккуратные GET-запросы и разбор HTML.

> ⚠️ Неофициальный доступ. Вёрстка портала может измениться; 
> используйте только свою учётную запись.

## Установка (преподавателю)

Понадобятся [uv](https://docs.astral.sh/uv/) и агент-харнесс, читающий
`~/.agents/skills` (ZCode, Codex, Qwen Code; Claude Code не поддерживается).

```bash
uvx --from git+https://github.com/MADTeacher/guap-teacher-mcp guap-teacher init
```

`init` сеет канонические навыки в `~/.agents/skills/guap-*` (существующие
файлы не перезаписывает) и печатает сниппеты MCP-конфига для ZCode /
Codex / Qwen Code — вставьте подходящий в конфиг вашего харнесса.
`guap-teacher` без аргументов — запуск MCP-сервера (stdio).

Проще всего попросить своего агента: «поставь guap-teacher отсюда
<ссылка на репозиторий>, подключи MCP и настрой навыки под мои правила
приёмки работ» — агент прочитает этот README и выполнит шаги сам.

Обновление движка (например, когда изменилась вёрстка портала):

```bash
uvx --refresh --from git+https://github.com/MADTeacher/guap-teacher-mcp guap-teacher --help
```

или просто попросите агента «обнови guap-teacher». Личные копии навыков
при этом не затрагиваются.

### Плагин ZCode

ZCode поддерживается нативно — плагином из этого репозитория:
**Plugin Marketplace → Add → Add Plugin Marketplace** → вставить путь
к клону этого репозитория → **Personal → guap-teacher-local →
guap-teacher → Install**. Плагин подключает MCP-сервер; после установки
попросите агента выполнить `guap-teacher init` — детали в
[guap-teacher/README.md](guap-teacher/README.md). Если guap-teacher уже
подключён напрямую — оставьте одно подключение.

Другие агентские харнессы (Codex, Qwen Code и любой, читающий
`~/.agents/skills`): плагин не нужен. `guap-teacher init` печатает
готовые сниппеты MCP-конфига (stdio) для ZCode / Codex / Qwen Code —
вставьте подходящий в настройки харнесса; навыки `guap-*` подхватятся
из `~/.agents/skills` автоматически.

## Запуск

MCP-сервер — команда `guap-teacher` без аргументов; в локальном клоне
репозитория для разработки — `uv run guap-teacher`.

Сниппет для конфига MCP-клиента (stdio), например ZCode / Codex / Qwen Code:

```json
{
  "mcpServers": {
    "guap-teacher": {
      "command": "uvx",
      "args": ["--from", "git+https://github.com/MADTeacher/guap-teacher-mcp", "guap-teacher"]
    }
  }
}
```

Для локального клона вместо uvx: `uv --directory <путь к клону guap-teacher-mcp> run guap-teacher`.

## Инструменты

**Сессия**
| Инструмент | Что делает |
|---|---|
| `authenticate` | Открывает браузер, вы входите через SSO руками, cookie сохраняются в `~/.guap-teacher-mcp/session.json` |
| `check_auth_status` | Проверяет, жива ли сессия |

**Отчёты студентов**
| Инструмент | Что делает |
|---|---|
| `list_reports` | Список отчётов с фильтрами (семестр, дисциплина, группа, студент, статус «ожидает проверки»/«принят»/«не принят», «только мои») |
| `get_report` | Страница проверки отчёта: статус, баллы, комментарии, поля формы |
| `download_report` | Скачать файл работы (по умолчанию в `<workspace>/.guap_mcp_tmp`, из workspace не выходит) |
| `grade_report` | **Write.** Поставить балл/статус/комментарий по отчёту (POST/PATCH); `mark=None` — оставить текущий балл, меняются только статус/комментарий |
| `get_student` | Карточка студента `/inside/profile/{id}`: группа, специальность, статус, email |

**Задания, дисциплины, материалы, объявления, расписание**
| Инструмент | Что делает |
|---|---|
| `list_tasks` / `get_task` | Мои задания (дисциплина, тип, дедлайн, видимость) и карточка с матрицей «студенты × отчёты» (кто сдал, кто ещё нет; ссылки просмотра и скачивания каждого отчёта) |
| `edit_task` | **Write.** Дедлайн / видимость / запрет загрузки после дедлайна / название / максимальный балл |
| `list_subjects` / `get_subject` | Дисциплины семестра (фильтры: группа, тип занятия, тип контроля) и карточка дисциплины (с группами и ссылками на ведомости) |
| `get_group_grades` | Ведомость «Список группы» (`/inside/groups/{subject}/{group}`): балл по каждому заданию и итог каждого студента |
| `get_group_info` | Карточка группы `/inside/groups/{gid}/info`: список студентов (ФИО, статус, студбилет, средний балл) — полезно для сопоставления ФИО в ведомости |
| `list_materials` / `download_url` | Материалы (файл/ссылка, дисциплина, группы, видимость, `material_id`/`edit_url`) и скачивание файлов портала |
| `create_material` | **Write.** Загрузить материал — файл (до 8 МБ) или внешнюю ссылку; по умолчанию скрыт и без почтового уведомления |
| `edit_material` | **Write.** Открыть/скрыть существующий материал (чекбокс `isPublic`; повторная рассылка уведомлений исключена) |
| `list_notices` / `get_notice` | Объявления (`/inside/professor/notice/*`): список с фильтрами (семестр, поиск) и карточка с таблицами студентов по группам |
| `create_notice` | **Write.** Создать объявление (заголовок, текст, дисциплины `idepc[]`, группы `grid[]`, тип, окно показа, вложение до 8 МБ) |
| `get_schedule` | Расписание на день/неделю с фильтрами группы/преподавателя/аудитории |

**Разведка** (для разработки)
| Инструмент | Что делает |
|---|---|
| `list_my_pages` | Стартовая страница кабинета: ФИО + все видимые разделы `/inside/*` |
| `discover_teacher_routes` | Карта маршрутов: путь (с `{id}`), статус, заголовок |
| `get_page` | Любая страница `/inside/*`: заголовок, текст, ссылки |

Значения фильтров у списков приходят в `filter_options` каждого ответа —
используйте их для уточнения следующего запроса. У списковых инструментов
(`list_reports`, `list_tasks`, `list_materials`, `get_schedule`) есть
параметр `filters`: `["teacher"]` — вернуть только нужные фильтры, `[]` —
без `filter_options` вовсе (полный список студентов/групп — сотни записей
и режет ответ MCP).

**Write-инструменты** (`grade_report`, `edit_task`, `create_material`,
`edit_material`, `create_notice`) меняют данные портала; правило
использования — в навыках: только с явного согласия преподавателя.
Новые POST-эндпоинты — только по явному запросу владельца репозитория
и отдельному ревью. Сводки ОП и статистика оценок
(`/inside/summary/*`, `/inside/evaluation/*`) не автоматизируются.
Заполнение официальных ведомостей (навык `guap-vedomost`) — локальная
операция: **выгрузка ведомости на портал не автоматизируется никогда**.

## Агентские навыки (Skills over MCP)

Готовые сценарии работы с сервером лежат в каталоге [`skills/`](skills/)
(один навык = `skills/<имя>/SKILL.md`). Сейчас там:

- **`guap-schedule`** — быстрое получение расписания: разрешение числового id
  преподавателя в фильтре расписания, выкачка периода ISO-неделями, разбор
  ячеек, подводные камни (пустая таблица без фильтра, HTTP 500 по ФИО,
  404 на хвостовых неделях).
- **`guap-review`** — проверка отчётов: выгрузка ожидающих, ревью PDF,
  журнал-протокол с вопросами на понимание, выставление оценок (только с
  явного согласия преподавателя).
- **`guap-kurs-review`** — проверка курсовых работ (проектов): поиск
  курсовых отчётов и ревью пояснительной записки (содержание и оформление
  по правилам ГУАП); балл/статус — через `grade_report`, только с явного
  согласия преподавателя.
- **`guap-vedomost`** — заполнение официальной ведомости преподавателя
  баллами с портала по заданным диапазонам. **Выгрузка ведомости на портал
  — только вручную, навык этого не делает никогда.**
- **`guap-digest`** — короткая утренняя сводка: что ждёт проверки,
  ближайшие дедлайны (годится для cron-запуска).

Сервер отдаёт навыки по MCP как read-only ресурсы (Skills over MCP):

| Ресурс | Что возвращает |
|---|---|
| `skill://index` | каталог доступных навыков |
| `skill://<имя>` | содержимое `SKILL.md` (text/markdown) |

Личные копии навыков преподавателя живут в `~/.agents/skills/<имя>/`
(каталог по умолчанию; переопределяется `GUAP_SKILLS_DIR`). ZCode, Codex
и Qwen Code читают этот каталог нативно; MCP-ресурсы `skill://` отдают
те же навыки любому клиенту с `resources/list` / `resources/read`
(личная копия побеждает при совпадении имени). Канонические навыки едут
внутри пакета; сравнить личные копии с каноном —
`guap-teacher skills diff`. Стабы `.zcode/skills/` остаются только для
разработки в самом репозитории.

Новый навык: создать `skills/<имя>/SKILL.md` (frontmatter `name` +
`description`) и, при необходимости, стаб в `.zcode/skills/<имя>/` —
ресурсы `skill://` сервер подхватит автоматически при следующем запуске.

Правила работы с кодом — в [AGENTS.md](AGENTS.md).
