# AGENTS.md — правила работы в этом репозитории

MCP-сервер для автоматизации преподавательской стороны **pro.guap.ru**
(Личный кабинет ГУАП). Публичного API у портала нет: это сервер-рендеренный
PHP (Laravel) с сессией `PHPSESSID` после SSO (Keycloak, `sso.guap.ru`).
Поэтому клиент работает по принципу «cookie + httpx + разбор HTML», как в
референсном проекте [overwaven/mcp-guap](https://github.com/overwaven/mcp-guap)
(студенческая сторона — наша зеркальная задача для преподавателя).

## Менеджер пакетов — только uv

Никаких `pip`, `requirements.txt`, `poetry`. Всё через uv:

```bash
uv sync                # создать/обновить .venv и uv.lock
uv add <pkg>           # добавить зависимость
uv add --group dev <pkg>  # dev-зависимость
uv run pytest          # тесты
uv run guap-teacher    # запустить MCP-сервер (stdio)
uv run playwright install chromium  # браузер для авторизации (один раз)
```

- Python 3.12 зафиксирован в `.python-version` — uv сам его скачает.
- `uv.lock` коммитим (это приложение, а не библиотека).
- Новые зависимости — только через `uv add`, не руками в `pyproject.toml`.

## Структура

```
src/guap_teacher_mcp/
  auth.py      # Playwright-логин через SSO -> файл сессии (cookie)
  client.py    # GuapClient: httpx, cookie, без следования за редиректами
  discover.py  # снятие карты маршрутов /inside/* (чистые функции + обход)
  pages.py     # парсеры конкретных страниц: отчёты, задания, дисциплины,
               #   материалы, объявления, расписание, профиль студента,
               #   матрица задания, ведомость «Список группы», карточка
               #   группы, parse_form_fields для write-форм
               #   (чистые функции на HTML-строке)
  skills.py    # загрузка навыков из skills/ и регистрация skill:// ресурсов
  server.py    # MCPServer-инструменты (stdio) + skill:// ресурсы
skills/        # канонические агентские навыки: skills/<имя>/SKILL.md
.zcode/skills/ # стабы для локального обнаружения навыков в ZCode
tests/         # только офлайн-тесты (без сети!)
```

## Соглашения по коду

- Идентификаторы и комментарии — английские; docstring'и MCP-инструментов —
  русские (они показываются пользователю в MCP-клиенте).
- Парсеры HTML — чистые функции в `discover.py` (обход маршрутов) и
  `pages.py` (конкретные страницы), их легко тестировать на фиксированном
  HTML. Сетевой код — отдельно в `client.py`.
- Селекторы опирать на классы портала: `h3.page__title` (заголовок),
  `h3.text-center` (ФИО), `kc-form-login` (маркер формы входа SSO).
- Списки портала: `/inside/professor/reports|tasks|materials` — таблицы с
  GET-фильтрами (semester/subject/group/status..., значения смотреть в
  `filter_options` ответа). Поиск дисциплин (`/inside/subjects/new`)
  срабатывает только при наличии параметра `searchtext` (можно пустого) и
  отдаёт 10 дисциплин на страницу (`per_page` игнорируется, `page`
  работает; парсер возвращает `page`/`last_page`, инструмент
  `list_subjects` умеет `page` и `all_pages` с паузой).
  Расписание (`/inside/students/classes/schedule/...`) без фильтра
  group/teacher пустое; id в его фильтрах — отдельное пространство значений.
- Вёрстка портала может поменяться — при поломке парсера сначала сверить
  селекторы, потом править код.

## Безопасность и этика (обязательные правила)

- **Только своя учётная запись и свои данные.** Никаких массовых обходов
  чужих страниц.
- Креды нигде не храним и не логируем: вход — всегда руками в браузере
  (Playwright), код видит только cookie.
- Файл сессии (`~/.guap-teacher-mcp/session.json`, переопределяется
  `GUAP_SESSION_PATH`) — секрет. Не коммитить, не печатать целиком в лог.
- Скачанные с портала файлы (отчёты, материалы) по умолчанию пишутся в
  `<workspace>/.guap_mcp_tmp` (переопределяется `GUAP_DOWNLOAD_DIR`) —
  персональные данные студентов не покидают workspace; папка в .gitignore,
  в git не коммитить.
- Инструменты read-only по умолчанию. Исключения — только по явному
  запросу владельца репозитория и отдельному ревью: `grade_report`
  (оценка/статус/комментарий по отчёту, ревью 2026-11-09; необязательный
  балл mark=None — 2026-11-10), `edit_task` (дедлайн/видимость/запрет
  загрузки; название/макс. балл — 2026-11-10), `create_material` (загрузка
  материала — файл или ссылка), `edit_material` (видимость материала) и
  `create_notice` (создание объявления) — решения владельца от 2026-11-10.
  Новые POST-эндпоинты — так же. Сводки ОП и статистика оценок
  (`/inside/summary/*`, `/inside/evaluation/*`) не автоматизируются —
  решение владельца от 2026-11-10. Заполнение официальных ведомостей —
  локальная операция (навык guap-vedomost); **выгрузка ведомостей на
  портал не автоматизируется никогда**. Создание отчёта за студента
  (`/inside/professor/reports/{task}/{student}/create`) исключено
  владельцем и в коде отсутствует.
- Обход страниц — с паузами (`delay_s`), `max_requests` ограничен. Не
  устраивать параллельных запросов к порталу.
- В `tests/` никаких сетевых тестов — только фикстуры HTML.

## Тестирование

```bash
uv run pytest
```

Перед коммитом: тесты зелёные, `uv run python -c "import guap_teacher_mcp.server"`
проходит без ошибок.
